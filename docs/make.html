How Duck Call was made, start to finish, so you can make your own OP-1 plugin. The short version: do most of your testing on your computer, not in the emulator, and only use the OP-1 for the final check.

1

Get the SDK

Everything comes from hundekraft's source download. It has the plugin headers, two templates, the packer and a plugin guide.

1.1Download and unpack

Get the source that matches the hundekraft on your OP-1, check its SHA-256, and unpack it. All the commands on this page run from ext/kennel inside it.

Read PLUGIN_GUIDE.md at the top of the download first. It covers the API, the screen rules and what a plugin may and may not touch.

The guide is written to be handed to an AI assistant like Claude. That's how Duck Call was built: describe what you want, give it the guide and the SDK, and work through it together.
# hundekraft 3.2 source and SDK
curl -LO https://hundekraft.github.io/op1-workshop/source/hundekraft-3.2-source.tar.gz
curl -LO https://hundekraft.github.io/op1-workshop/source/hundekraft-3.2-source.tar.gz.sha256
shasum -a 256 -c hundekraft-3.2-source.tar.gz.sha256
tar xzf hundekraft-3.2-source.tar.gz
cd hundekraft-3.2-source/ext/kennel

# what you'll use
synth_sdk/op1_plugin.h        # the API
synth_sdk/template/fx         # an effect to start from
synth_sdk/template/synth      # a synth to start from
synth_sdk/kennel/kn_exports.c # everything a plugin can call
tools/kennel/pack.py          # builds the .knl

1.2Copy a template

Start from the effect template. It's a tremolo with a soft clipper, small enough to read in one go. Give your copy a new name in the folder, the file, the symbol and plugin.json, and keep that name for every future version.

An effect gets 64 samples at a time and four knobs, in fixed point (32767 means 1.0). Keep state in an array of three, one per FX position: synth, drums and master.

mkdir -p synth_sdk/plugins/myfx
cp synth_sdk/template/fx/myfx.c    synth_sdk/plugins/myfx/
cp synth_sdk/template/fx/plugin.json synth_sdk/plugins/myfx/
2

Test on your computer

This is the step that saves the most time. Compile your effect with your computer's own C compiler, run audio through it, and listen to a WAV file. A change takes seconds to try, and crashes show up as readable errors instead of a frozen OP-1.

2.1The fx-host kit

The SDK's header expects a small file of stand-ins for the OP-1 (harness/op1_host.h), but the 3.2 download leaves it out. The fx-host kit in Duck Call's repo has one, plus a runner.

It plays 8 seconds of a chord pad over a kick at 120 BPM through your effect and writes dry.wav and wet.wav. The kick doubles as the sidechain, and the beat clock runs at 120 BPM, so tempo and sidechain effects work too.

Leave the sanitizers on. They catch out-of-bounds reads and overflow, the bugs that crash or click on the OP-1.

git clone https://github.com/ssimorka/duck-call
K=$PWD/synth_sdk          # from ext/kennel
cd duck-call/tools/fx-host

cc -O2 -Wall -fsanitize=address,undefined -I. -I$K \
   -DPLUGIN_C="\"$K/plugins/myfx/myfx.c\"" -DFX=FX_myfx \
   fx_host.c -lm -o fx_host

# the four knobs, 0 to 32767: blue green white red
./fx_host 8000 16000 4000 32767
# knobs 8000 16000 4000 32767: level in -14.8 dB,
# out -14.7 dB, 0 clipped samples. Wrote dry.wav and wet.wav.

2.2And the emulator?

It's useful at the end, to check your plugin against the real firmware, but it's slow to work with day to day. For Duck Call the loop was: change the code, run fx-host, listen, repeat. Then pack it and try it on the OP-1.

CheckWhere
Does it sound right?fx-host, listening to wet.wav
Does it crash or overflow?fx-host, with the sanitizers
Is the screen art valid?harness/svg_check.py
Does it load and run?pack.py, then the OP-1
3

Build the .knl

The OP-1 runs a Blackfin chip, so the final build needs a Blackfin cross compiler. Your computer's normal compiler can't make OP-1 code.

3.1The compiler

You need bfin-elf-gcc with libgcc. hundekraft 3.x uses GCC 13.3.0, and nobody ships it ready-made, so you build it once from GNU binutils 2.42 and GCC 13.3.0. build-bfin-toolchain.sh does it with the same options Duck Call's compiler used. It takes 30 to 60 minutes.

On a Mac, do it in a Linux VM or container. If a build step stops halfway, run make again and it picks up where it left off.

# one script does it all (Linux or a Linux VM)
duck-call/tools/build-bfin-toolchain.sh
export PATH=$HOME/bfin/tc/bin:$PATH
bfin-elf-gcc --version   # bfin-elf-gcc (GCC) 13.3.0

# the gcc options it uses
--target=bfin-elf --enable-languages=c --without-headers
--with-newlib --disable-shared --disable-threads --disable-libssp
--disable-multilib --disable-bootstrap
make all-gcc all-target-libgcc

3.2Pack it

pack.py compiles your folder and writes one .knl file. It stops with a clear message if you call something the OP-1 doesn't offer, or if your screen art breaks a rule.

python3 tools/kennel/pack.py synth_sdk/plugins/myfx -o build/myfx.knl
# build/myfx.knl: 836 bytes, sections .text 604,
# .rodata 12, .data 0, .bss 12; ... imports none
4

Try it on the OP-1

Install through the hundekraft workshop like any other plugin. Same name replaces the old version, so each try only takes a minute.

4.1Install and iterate

  1. Open the hundekraft workshop in Chrome.
  2. Go to Your plugins, choose Add your plugin files and pick your .knl.
  3. Connect my OP-1, Review changes, Send, then press T1.
  4. Load it from the FX list, play, and take notes. A phone video of the screen helps a lot.
Things that bit us
Knob wordsRaw words have the filter slot's range. Read them through op1_fx_param_q15().
PressesOnly blue, green and white get a page 2. Red can be stepped or a switch.
Screen bottomKeep art above about y 146 on effect screens.
SpeedNo floats in the audio path. Fixed point and lookup tables only.
5

Screens

A screen is two parts: still art in an SVG, drawn once, and a function that draws the moving parts as lines every frame. Read docs/screen-art.md for the rules.

5.1How Duck Call's screen works

The marquee, rays, clouds and knob scales are the SVG. The ducks, waves, curtains, rifle and sight are about 500 lines a frame from duckcall_screen.c. Things behind are clipped against what's in front.

A script, gen_screen.py, writes both the SVG and the moving parts' shapes from the same numbers, so they always line up. The design was worked out first in a web prototype, then ported.

RuleWhy
ColorsBlue, green, white and red each belong to a knob. Indigo and grays for the rest.
CostEach line costs time. The busiest stock-style screens draw around 600.
SVGSimple paths only: M, L, H, V, C, S, Z. No fills on open shapes.
Still when silentFreeze when there's no sound, so it doesn't fight the music for CPU.
